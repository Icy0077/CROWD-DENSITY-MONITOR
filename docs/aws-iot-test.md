# AWS IoT Core connection test

The manual test script at `scripts/test_aws_iot.py` performs one controlled MQTT round trip using the existing `edge/mqtt/publisher.py` configuration.

It does not run as part of the edge pipeline and is never started automatically.

## Before running

Configure the required variables in a local `.env` file or in the process environment:

```dotenv
AWS_IOT_ENDPOINT=your-endpoint-ats.iot.your-region.amazonaws.com
AWS_IOT_CLIENT_ID=cloudcrowd-edge-01
AWS_IOT_TOPIC=cloudcrowd/telemetry
AWS_IOT_CA_PATH=C:\path\to\AmazonRootCA1.pem
AWS_IOT_CERT_PATH=C:\path\to\device-certificate.pem.crt
AWS_IOT_PRIVATE_KEY_PATH=C:\path\to\private-key.pem.key
```

The files must exist and contain the Amazon Root CA, device certificate, and device private key supplied through your AWS IoT provisioning process. Do not put certificate or private-key contents in source code.

See [aws-iot-setup.md](aws-iot-setup.md) for the complete configuration and repository security rules.

## Run manually

From the project root:

```powershell
.\.venv\Scripts\python.exe .\scripts\test_aws_iot.py
```

The timeout can be changed without changing configuration:

```powershell
.\.venv\Scripts\python.exe .\scripts\test_aws_iot.py --timeout 20
```

The script loads `.env` through the existing `edge.mqtt.publisher` configuration. It does not accept credentials or certificate contents as command-line arguments.

## Test sequence

The script:

1. Validates that AWS IoT configuration is present.
2. Validates the CA, device certificate, and private-key files through the existing publisher.
3. Configures MQTT over TLS using those files.
4. Connects to the configured endpoint.
5. Subscribes to `AWS_IOT_TOPIC`.
6. Publishes exactly one telemetry JSON payload generated by `build_telemetry()`.
7. Waits for the matching message on the subscribed topic.
8. Disconnects in a `finally` block.

The test payload uses the existing telemetry schema and the location ID `aws_iot_connection_test`.

## Output

Only status and safe error information is printed. The script does not print endpoint credentials, certificate contents, or private-key contents.

Successful output has this form:

```text
CONNECTION: PASS
SUBSCRIBE: PASS
PUBLISH: PASS
MESSAGE_RECEIVE: PASS
```

Possible failures are reported as configuration, connection, timeout, or MQTT test errors. Missing files and incomplete variables stop the test before any connection is attempted.

## Safety boundaries

- This is an opt-in script and is not called by the edge pipeline.
- It uses the configured AWS IoT endpoint only when the user runs it manually.
- It does not use AWS access keys.
- It does not print secrets or certificate material.
- It publishes only one test telemetry message.
